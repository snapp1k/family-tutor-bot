# Family Tutor — финальная семейная версия (Windows → Ubuntu VM)

**Версия:** 2026-11-22, anti-loop v2 / Pro-credit-ready.

Бот предназначен для одного родителя, одного ученика и одного доверенного тестировщика. Родитель публикует задания, ребёнок присылает мысли и фото, репетитор даёт небольшие объяснения и вопросы. Родитель получает результаты, видит наблюдаемые попытки запросить готовые ответы, просматривает фотографии и сам принимает работу. «Определить по фото, писал ли человек с ИИ» достоверно невозможно; модель не должна заявлять обратное.

**УВАЖАЙТЕ ПРИВАТНОСТЬ:** объясните ребёнку, какие сообщения и фото видит родитель и как долго они сохраняются. Не размещайте токен, содержимое `.env`, резервные копии и фотографии учеников в открытом доступе.

## 1. Исправления относительно старой версии

- Старый `tutor.py` превращал почти любой ответ длиной менее 15, более 500 символов, без вопросительного знака либо с `x = 2` в одну и ту же фразу «Начнём с твоих рассуждений…». Теперь это удалено: нормальный ответ сохраняется, даже если нет `?`.
- Прямые просьбы «дай готовый ответ» раньше обрабатывались единственной заготовкой без обращения к нейросети. Теперь запрос помечается как `answer_request`, но репетитор адаптирует объяснение к конкретному вопросу ученика.
- Если модель действительно прислала почти дословный повтор недавнего ответа или явный заголовок `Ответ:`, приложение просит её переформулировать **один раз**. При второй неудаче выдаётся безопасная, но тематическая локальная подсказка; она не выдаётся за проверку нейросетью.
- Контекст содержит последние **24** события (каждое ограничено по длине) из SQLite по паре (задание, Telegram ID), а не обнуляется между обращениями.
- При реальных ошибках подключения (401, 429, Codex timeout) бот показывает техническую ошибку, а не притворяется, будто изучил фотографию.
- В запросах API используется структурированный JSON, фото и `store: false`.
- Добавлены `OPENAI_API_KEY`, `API_MODEL`, `MAX_DAILY_TURNS`, `/health`, Linux systemd, `doctor.py`, `backup_ubuntu.sh` и регрессионные тесты.

**Ограничение:** даже строгий промпт, схематический JSON и фильтры не дают гарантии, что умная модель никогда не выдаст ответ. Надёжная педагогическая проверка — просьба ученику самому объяснить решения и контроль отца.

## 2. Выберите способ оплаты/авторизации — важное отличие

### A. РЕКОМЕНДУЕТСЯ: `BACKEND=openai_api`

На дату сборки OpenAI позволяет **подходящим** владельцам ChatGPT Pro $200 активировать **до $200 API-кредитов за полный оплаченный месячный период**. Это отдельный официальный бонус; он **не равен** обычным лимитам Codex и сам по себе ещё не активирован. Первый период пропорционален остаточным дням, нужно соблюсти срок владения подпиской и региональные условия. Официальная инструкция:

https://help.openai.com/en/articles/20001626-api-credits-benefit-for-eligible-chatgpt-subscriptions

**Отец сам делает:**

1. Заходит под своим Pro 200 аккаунтом в ChatGPT → Settings → Billing.
2. Находит **API credits benefit**, выбирает принадлежащую ему организацию на `platform.openai.com` и подтверждает активацию.
3. Проверяет Credit grants и доступный баланс в API Billing, только после этого создаёт API-ключ своего проекта.
4. Не добавляет платежный метод и не включает Auto Recharge, если условие — *не тратить ничего сверх подписки*. Если на организации уже есть платный баланс/автосписание, проверьте и отключите их до тестов.
5. В `.env` указывает:

```dotenv
BACKEND=openai_api
OPENAI_API_KEY=sk-INSERT_REAL_KEY_HERE
API_MODEL=gpt-4.1-mini
MAX_DAILY_TURNS=60
```

Указанная модель — экономичный вариант с поддержкой зрения и JSON-схемы. Кредиты при наличии гранта расходуются по API-тарифам; на исчерпании лимита бот выдаст ошибку, а не обойдёт ограничения. Сумму гранта, доступные модели и расходы проверить в аккаунте перед использованием. API-ключ находится **только на Ubuntu-сервере**, не в чате Telegram.

### B. ЭКСПЕРИМЕНТАЛЬНО: `BACKEND=codex`

Подключение через Codex CLI с `codex login --device-auth` под **Linux-пользователем `tutorbot`**, в чьём профиле выполняется фоновый процесс. Codex выполняется один раз на каждый вопрос с CLI `codex exec` (эпизодически и без инструментов по инструкции). Проверяем, что `codex login status` говорит `ChatGPT`. При API-key входе режим `codex` намеренно остановится, чтобы случайно не потратить деньги.

```dotenv
BACKEND=codex
CODEX_MODEL=
MAX_DAILY_TURNS=60
```

**Важно:** личные ChatGPT-учётные записи предназначены для индивидуального использования. Вопрос права применять личную Pro-сессию как сервис обработки запросов других людей остаётся отдельным: не выдавайте доступ к ChatGPT-аккаунту ни ребёнку, ни другим лицам и проверьте применимость текущих условий. Для семейного приложения предпочтительнее официальный API-кредитный механизм. Режим CLI также медленнее и может меняться между версиями.

### C. Оффлайн-альтернатива: `BACKEND=ollama`

Локальный сервер Ollama `http://127.0.0.1:11434`, модель `gemma3:4b`. Для качественной обработки фото виртуалке нужно достаточно оперативной памяти и подходящая производительность. Это отдельная установка; не входит в скрипт Ubuntu. Качество и способности будут отличаться.

### D. `BACKEND=mock`

Только тестирование кнопок и хранилища. Не анализирует фото; в реальной работе с учеником **не использовать**.

## 3. Установка на Ubuntu 24.04 / 26.04 (виртуальная машина)

**Системные предпосылки:** Ubuntu с Python 3.12+, интернет-доступом, DNS, исходящим HTTPS, часами через NTP. Рекомендуем 2 виртуальных CPU, 4 ГБ RAM минимум для API или Codex CLI; для Ollama может потребоваться существенно больше. Проверьте `timedatectl` и сеть.

Перенесите **ВЕСЬ** каталог `FamilyTutor_Final` на Ubuntu любым удобным способом (SCP, сетевой диск или общая папка). Если хотите сохранить историю Windows, скопируйте **из старой Windows-папки** в новый каталог `.env` и директорию `data` **до** запуска установщика. В `.env` старого проекта, возможно, ещё `BACKEND=mock`: изменить вручную на выбранный бэкенд.

**Остановите процесс Windows-бота до запуска Ubuntu**: один токен BotFather не должен одновременно обслуживаться двумя polling-процессами, иначе ошибка Telegram 409.

В каталоге проекта:

```bash
sudo bash install_ubuntu.sh
sudo nano /opt/family-tutor/.env
```

Если хотите начать с нуля, скрипт самостоятельно создаст `.env` со случайными кодами доступа (через `setup.py`). Вставьте токен от BotFather, активируйте выбранный бэкенд и сохраните. Файл должен оставаться с правами `0600`.

Для рекомендованного режима API **Codex CLI на виртуалке не нужен**. Выполните:

```bash
sudo systemctl start family-tutor
sudo systemctl status family-tutor --no-pager
sudo journalctl -u family-tutor -n 80 --no-pager
sudo -u tutorbot -H /opt/family-tutor/.venv/bin/python /opt/family-tutor/doctor.py
```

При необходимости сначала проверяйте ключ без Telegram (запрос расходует немного API-кредитов):

```bash
sudo -u tutorbot -H /opt/family-tutor/.venv/bin/python /opt/family-tutor/smoke_test.py --backend openai_api
```

### Запуск с подпиской Codex CLI на Ubuntu

Сначала убедитесь, что установлен **Node.js LTS** и `npm`. На VM установите Codex CLI (если Node/npm уже есть):

```bash
sudo npm install -g @openai/codex@latest
codex --version
```

Для режима сервиса важно авторизовать **именно `tutorbot`, а не обычного пользователя или root**:

```bash
sudo -u tutorbot -H codex login --device-auth
sudo -u tutorbot -H codex login status
sudo -u tutorbot -H /opt/family-tutor/.venv/bin/python /opt/family-tutor/smoke_test.py --backend codex
```

Device authorization выводит адрес и код, которые **вводит сам отец** в браузере под своей подпиской. Не отправляйте код третьим лицам и не копируйте файл авторизации через Telegram. Если `codex` не найден в команде `sudo -u tutorbot`, проверьте `command -v codex`, `sudo -u tutorbot -H env`, путь `/usr/local/bin` и параметр `Environment=PATH=...` в systemd. После успеха поменяйте в `.env` `BACKEND=codex`, затем:

```bash
sudo systemctl restart family-tutor
sudo journalctl -fu family-tutor
```

**Внимание:** `codex login --device-auth` может потребовать предварительного включения device-code login в настройках ChatGPT в зависимости от версии продукта. Если авторизация не проходит, смотрите встроенную подсказку CLI. Не пересылайте `.codex/auth.json`.

### Управление службой

```bash
sudo systemctl status family-tutor
sudo systemctl restart family-tutor
sudo systemctl stop family-tutor
sudo journalctl -u family-tutor -n 100 --no-pager
```

Служба автоматически стартует после перезагрузки (`systemctl enable`), автоматически перезапускается после ошибки, работает под отдельным непривилегированным пользователем `tutorbot`, а не под root. Не открывайте входящие порты на VM: Telegram использует исходящий long-polling.

## 4. Первичная настройка Telegram-аккаунтов

**Роли задаются ID, не никами** — смена `@username_student` на `@username_parent` не добавит прав.

- Отец `@username_parent`: `/pair parent СЕКРЕТНЫЙ_КОД_ОТЦА`.
- Ученик `@username_student`: `/pair student СЕКРЕТНЫЙ_КОД_УЧЕНИКА`.
- Тестировщик `@username_tester`: `/pair tester СЕКРЕТНЫЙ_КОД_ТЕСТИРОВЩИКА`.

Коды хранятся в `/opt/family-tutor/.env` под полями `PARENT_PAIR_CODE`, `STUDENT_PAIR_CODE`, `TESTER_PAIR_CODE`. Если переносите старую SQLite, зарегистрированные роли остаются. *Телеграм-ники указаны для удобства, но не подходят для авторизации.*

Взаимодействие:

```text
Отец:
/new Алгебра, упр. 53, решить два примера (затем можно прислать фото)
/publish
/tasks
/report 1
/evidence 1
/approve 1
/retry 1
/delete 1
/health

Ученик:
/tasks
/select 1
[пишет самостоятельный шаг или присылает фото]
[спрашивает, что конкретно непонятно]
/done

Тестировщик:
/mode parent
/mode student
```

**Важно для приёма:** команда `/done` лишь отправляет материал на проверку. ТОЛЬКО отец принимает работу кнопкой или `/approve`. Отчёт описывает шаги и конкретные наблюдения; бот не имеет надёжного детектора ИИ-авторства.

## 5. Диагностика в Telegram и на VM

| Что видно | Причина | Что делать |
| --- | --- | --- |
| «Демонстрационный режим» | `BACKEND=mock` | Изменить `.env`, перезапустить службу |
| «Codex не авторизован» | CLI login сделан под другим Linux-пользователем | `sudo -u tutorbot -H codex login --device-auth` |
| «Codex CLI не найден» | глобальный npm не установлен/недоступен PATH | `command -v codex`, `sudo -u tutorbot -H codex --version` |
| «API HTTP 401» | неверный ключ | создать секрет проекта в API Platform |
| «API HTTP 429» | исчерпаны грант, RPM/TPM, ограничения | проверить Billing и Limits; НЕ включать платежи без решения отца |
| Бот молчит | процесс упал / неверный токен | `systemctl status`, `journalctl` |
| `Conflict: terminated by other getUpdates request` | два процесса используют один BotFather token | выключить бот на Windows |
| Бот отвечает одинаково | старый `tutor.py` или одинаковый текст модели | проверить anti-loop релиз и историю, тесты ниже |
| Бот не видит фото | ошибка обработки или лимиты размера | прислать чёткий JPG/PNG/WEBP до 8 МБ |
| Бот спрашивает первое действие после 10 сообщений | история стала неактуальной или завис режим | `/health`, `doctor.py`, тесты; объяснить конкретный шаг |

Проверка без сети (модель подменена тестовым адаптером):

```bash
cd /opt/family-tutor
sudo -u tutorbot -H .venv/bin/python -m unittest discover -s tests -v
```

Папка `tests` содержится в архиве исходников, но установщик не переносит её в `/opt`. Поэтому тесты запускайте **в исходном каталоге на Ubuntu** или скопируйте каталог `tests` туда. При необходимости тесты запускаются на Windows так: `py -3 -m unittest discover -s tests -v` из каталога проекта (с установленными пакетами).

## 6. Резервная копия

На Ubuntu:

```bash
sudo bash /opt/family-tutor/backup_ubuntu.sh
```

Архив появляется в `/var/backups/family-tutor`, доступен root и содержит `.env`, базу и фото — **секретный архив**, не передавайте его сторонним лицам. Восстанавливать стоит на выключенной службе, учитывая права владельца и текущее состояние SQLite.

## 7. Обновление и миграция

На Windows остановить старый `run_windows.bat`. Перенести `.env` и `data/` из старой папки в новый каталог проекта. Сохраняйте исходные коды роли, ID, SQLite, фото и токен. Затем перенести каталог проекта на Ubuntu и выполнить `sudo bash install_ubuntu.sh`. Скрипт при повторном запуске обновляет код, не перезаписывает существующие `.env` и `data`.

Перед обновлением живой службы **сделайте резервную копию, выключите процесс и только потом установите обновление**. После завершения настроек снова включите службу.

## 8. Безопасность и операционные ограничения

- `@username` никогда не является ключом доступа; роли назначаются однажды на числовой Telegram ID.
- Учебное задание, фото, история и сообщения школьника считаются недоверенными; модель не исполняет их инструкции по смене роли.
- `codex exec` запускается в read-only sandbox, без `shell=True`, с передачей контекста через stdin; это **дополнительная**, но не абсолютная защита. Для полноценного использования чужих запросов предпочтительнее официальный API.
- История событий удаляется через 30 дней, однако оригинальные фотографии *условий* остаются до `/delete`, а резервные копии требуют отдельной политики удаления.
- Используйте только личные Telegram-чаты, не группы; учитывайте, что Telegram и провайдер модели обрабатывают сообщения и изображения согласно собственным условиям.
- API-кредиты и подписочные лимиты не одинаковы. Промокредиты могут закончиться, и без пополнения API остановится. Не обещайте безлимитности.
- Строгой математической гарантии «ученик никогда не заставит модель ответить» **нет**; проверяйте работу самим взрослым.
